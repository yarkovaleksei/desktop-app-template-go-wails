# Интерфейс Desktop App

Работай в корне репозитория. Правила интерфейса и чем проверяется каждое — [docs/ui.md](../../../docs/ui.md); слои фронтенда и шаги новой страницы, настройки, метода — [docs/development.md](../../../docs/development.md#как-добавить); правила TypeScript — [docs/code-style.md](../../../docs/code-style.md#typescript-и-react). Если скилл расходится с ними, верны они.

## Перед правкой

1. Прочитай [docs/ui.md](../../../docs/ui.md) целиком: большинство правил держит обзор, а не команда.
2. Изучи затронутую страницу, её тест, её сценарий в `frontend/e2e/` и общие компоненты `frontend/src/components/`. Соседние сценарии без нужды не переделывай.
3. Нужны данные или действие Go — сначала метод в `DataSource` по рецепту [Метод сервиса](../../../docs/development.md#метод-сервиса) (`app-code-style`).

## Порядок работы

1. **Компоненты.** Сначала готовый компонент MUI по его назначению (`Switch`, `ToggleButtonGroup`, `Alert`, `Accordion`, `Dialog`); своя обёртка — только если в MUI нужного нет. У элемента управления — подпись, по которой его находят роль и имя.
2. **Тексты.** Каждая строка — ключ `t("…")`; ключ сразу в `frontend/src/i18n/ru.ts` и `frontend/src/i18n/en.ts`. Множественное число — формами `Intl.PluralRules`, как `home.uptime`.
3. **Тема.** Цвета, отступы и шрифты — из темы через `sx`; новый цвет — токен в `frontend/src/theme/tokens.ts` для обеих тем.
4. **Состояния.** Загрузка, ошибка (уведомление с текстом по коду), недоступность (элемент выключен, рядом пояснение — как переключатель работы в фоне без трея).
5. **Стор.** Действие — в `frontend/src/store/appStore.ts`, ошибка — через `run`; компонент привязки не зовёт.
6. **Тест страницы** на `fakeSource`: элемент находится по роли и имени, действие вызывает метод источника (образец — `frontend/src/pages/SettingsPage/SettingsPage.test.tsx`).
7. **Сквозной сценарий** в `frontend/e2e/`: обе темы, оба языка, основное действие; состояние задаётся параметрами адреса моков (`mockOptionsFromSearch` в `frontend/src/api/mockSource.ts`), а не правкой кода.

## Проверка

1. Адресно во время работы: во `frontend/` — `yarn test <файл>`, `yarn typecheck`, `yarn lint`.
2. `wails3 task test:e2e` — сценарии Playwright на моках.
3. **В браузере на моках:** `wails3 task ui` (для Claude Code — конфигурация `ui` в `.claude/launch.json`). Окно браузера 960×600, светлая и тёмная тема, русский и английский: ничего не обрезано, прокрутка у содержимого, фокус виден, с клавиатуры всё доступно. Состояние — параметрами адреса, например `/?lang=en&theme=dark#/settings`.
4. **В окне приложения**, если правка касается Go, окна или трея и окружение позволяет: `wails3 task dev`. Браузер на моках не подтверждает настоящие данные, трей и системные диалоги — если окно проверить нельзя, так и скажи.
5. Перед коммитом — `wails3 task check` (`app-code-style`).

## Что сообщить

Что изменено на странице; ключи текстов на обоих языках; тесты и сценарии — добавленные и их итог; что проверено в браузере (размер окна, темы, языки) и в окне приложения; что не проверено и почему.
