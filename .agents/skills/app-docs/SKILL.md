# Документация Desktop App

Работай в корне репозитория. Какой документ чем владеет и когда его обновлять — [docs/README.md](../../../docs/README.md); какой документ владеет областью кода — [карта кода](../../../docs/code-map.md). Правило «документация и код» — в разделе «Документация и код» `AGENTS.md`.

## Порядок

1. **Тип изменения.** Что изменилось для читателя: поведение, команда, настройка, событие, метод сервиса, формат поставки, workflow, правило кода или интерфейса, порядок работы агента.
2. **Документ-владелец.** Найди строку в таблице [docs/README.md](../../../docs/README.md) по графе «Когда обновлять» и документы области в [карте кода](../../../docs/code-map.md). У сведения один владелец: остальные документы ссылаются на него, а не повторяют.
3. **Правка — в том же коммите, что код.** Описывай то, что есть сейчас, и почему; не пересказывай код и не пиши историю изменений («раньше было…»). Подробности устройства — в комментариях рядом с кодом.
4. **Парные документы.** `README.md` правится вместе с `README.en.md`: одинаковые разделы и имена пакетов проверяет `internal/archtest`, смысл — обзор. Задача Taskfile добавлена или удалена — таблица «Команды» в обоих README и блок команд в `AGENTS.md`.
5. **Проверка.** `wails3 task check:docs`: ссылки и якоря, пути в обратных кавычках, задачи `wails3 task …`, скрипты `yarn …`, актуальность карты кода. Смысл текста она не проверяет: перечитай изменённый раздел глазами человека, который не видел код.

## Частые случаи

| Изменение | Документ |
| --- | --- |
| Метод сервиса, событие, настройка, каталог, переменная окружения | [docs/development.md](../../../docs/development.md) |
| Трей, автозапуск, уведомления, окно, фоновая проверка | [docs/desktop.md](../../../docs/desktop.md) |
| Новое правило кода или его проверка | [docs/code-style.md](../../../docs/code-style.md) |
| Новое правило интерфейса | [docs/ui.md](../../../docs/ui.md) |
| Формат поставки, состав пакета, иконка | [docs/packaging.md](../../../docs/packaging.md) |
| Задачи `release:*`, workflow `release` | [docs/release.md](../../../docs/release.md) |
| Любой файл `.github/workflows/` | [docs/ci.md](../../../docs/ci.md) |
| Новый пакет или страница | карта кода — скилл `app-code-map` |

| Новый или удалённый документ | [docs/README.md](../../../docs/README.md) |

## Если документ и код расходятся

Правило продукта — верен документ, исправь код или спроси владельца; внутреннее устройство — верен код, исправь документ. Расхождение не разрешай молча: в итоге работы назови его и какую сторону исправил.

## Что сообщить

Какие документы обновлены и почему именно они; найденные расхождения; итог `check:docs`.
