# Инициализация проекта из шаблона

Работай в корне копии шаблона: репозиторий, созданный на GitHub кнопкой «Use this template», или клон шаблона. Порядок для человека и подробности — раздел «Как начать проект из шаблона» в [README.md](../../../README.md#как-начать-проект-из-шаблона). Инструмент — `scripts/init`; что он меняет, сказано в комментарии пакета в `scripts/init/main.go`.

## Перед запуском

1. `git status --short` пуст, а в `go.mod` — модуль шаблона `github.com/yarkovaleksei/desktop-app-template-go-wails`. Иначе инструмент откажется работать: незакоммиченное владелец коммитит или убирает сам; если имён шаблона уже нет, проект уже инициализирован — сообщи и остановись.
2. Спроси у владельца одним сообщением то, чего нет в поручении:
   - название продукта («My App»);
   - слаг — имя бинаря, каталогов и пакетов (по умолчанию из названия: `my-app`);
   - репозиторий GitHub `владелец/имя`; если у копии есть `origin` (`git remote get-url origin`), предложи значение из него, иначе спроси; `origin` владелец настраивает сам;
   - описание в одну строку — оно попадёт в файлы сборки, пакеты, ярлык и README;
   - правообладателя для `LICENSE` (по умолчанию — владелец репозитория) и свой цвет иконки `#RRGGBB`, если нужен.
3. Назови правила, по которым инструмент выведет остальное, и спроси, менять ли их: модуль Go `github.com/<репозиторий>`, идентификатор `io.github.<владелец>.<слаг без дефисов>`, префикс окружения — слаг в верхнем регистре с `_`, скиллы `<слаг>-*`, год — текущий. Сами значения напечатает пробный запуск.

## Запуск

1. Пробный запуск: `go run ./scripts/init -name "…" -repo владелец/имя -description "…" [-slug …] [-module …] [-id …] [-author …] [-color …] -dry-run`. Ошибка в значении называет флаг и допустимый вид — исправь значение вместе с владельцем.
2. Покажи владельцу имена проекта (раздел «Имена проекта» вывода — в нём и производные значения) и список изменений из вывода: сколько файлов меняется, что переименовывается и удаляется. Отметь, что `git status` после пробного запуска чист.
3. По согласию владельца запусти ту же команду без `-dry-run`. Без согласия не запускай: изменения затрагивают почти все файлы.

## Следующие шаги

Инструмент печатает их в конце. Пройди по порядку:

1. `wails3 task deps`, `wails3 task bindings`, `wails3 task fmt`, `wails3 task icons:derive`, `wails3 task docs:map`.
2. `wails3 task check` — должен быть зелёным. Упал — разбери причину по выводу и не чини её правкой файлов наугад: пропущенный следующий шаг повтори, а дефект инициализации (оставшееся имя шаблона, файл, который после замены не проходит линтер или тест) назови владельцу — его нужно исправить и в `scripts/init` шаблона.
3. Инструмент уже добавил свои изменения в индекс; после следующих шагов добавь и их (`git add -A`). Покажи владельцу `git status --short` и предложи коммит «Инициализировать проект из шаблона». Commit и push — только по его поручению (раздел «Границы поручения» в `AGENTS.md`).
4. Остальное — дело владельца, назови его: своя иконка вместо шаблонной, снимок окна для сайта, `spec/docs/project.md`, цель первого плана, GitHub Pages для сайта.

## Отчёт

Имена проекта, результат `check`, что осталось из следующих шагов и что не проверено.
