# Сборка Desktop App

Работай в корне репозитория. Форматы, состав пакетов, AppArmor и способы проверки описаны в [docs/packaging.md](../../../docs/packaging.md); команды — в `Taskfile.yml`. Если скилл расходится с ними, верны они.

## Объём поручения

- Сборка не разрешает commit, push, тег, выпуск и установку пакета в систему. `sudo apt install` и подобное выполняет владелец сам или агент по отдельному поручению.
- Изменение рецепта сборки не разрешает пересборку всех форматов: проверяй изменённое адресно. Полную матрицу по своей инициативе не запускай.
- Сборки длинные: запускай их в фоне и не опрашивай без нужды. Журналы и временные файлы — в scratchpad или `/tmp`.

## Что собирается где

Кросс-сборки нет: `wails3 task package` собирает пакеты только текущей ОС. Linux — deb, rpm, пакет Arch, AppImage; Windows — установщик NSIS и переносимый exe; macOS — dmg. Что нужно для сборки на каждой ОС — таблица «Где что собирается» в [docs/packaging.md](../../../docs/packaging.md#где-что-собирается). Пакеты других ОС собирает CI по тегу (`app-release`).

## Сборка

1. Версия сборки: `wails3 task version`. Без тега — `0.0.1-dev`; суффикс `-dirty` значит, что в дереве незакоммиченные изменения: такой пакет не выдавай за снимок HEAD.
2. Бинарь из исходников: `wails3 task build` (в `bin/`), затем `wails3 task smoke` — окно открылось и фронтенд ответил. Такая сборка формата не знает и обновляться не умеет.
3. Пакеты: `wails3 task package` — в `bin/`. Пробная сборка с номером: `wails3 task package APP_VERSION=1.2.3`.
4. Имена выпуска и суммы, если нужны: `wails3 task release:collect APP_VERSION=1.2.3` — пакеты текущей ОС в `dist/` и `SHA256SUMS-<ОС>.txt`.

## Проверки

1. **Состав пакета** — способом из таблицы «Проверка пакета» в [docs/packaging.md](../../../docs/packaging.md#проверка-пакета): версия, зависимости, файлы, метка формата. Нет инструмента (`rpm`, `7z`, `zstd`) — так и скажи, что не проверено.
2. **Формат в приложении** — `--version` установленного или распакованного бинаря печатает свой формат последним полем.
3. **Суммы** — `sha256sum -c` по файлу сумм в `dist/`.
4. **Окно как из меню (Linux)** — `wails3 task smoke:desktop` после того, как пакет установлен; по умолчанию `/usr/bin/desktop-app`, другой бинарь — `BIN=…`. Окно на несколько секунд появится на экране — предупреди владельца.

Запуск окна из оболочки агента на Linux ничего не доказывает: дочерние процессы Claude Code и Codex наследуют их профиль AppArmor с правом на user namespace, и окно открывается даже там, где из меню падает. Для установленного пакета — только `smoke:desktop`.

Песочница WebKit остаётся включённой. Не ставь `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS`, не выключай AppArmor и не меняй `kernel.apparmor_restrict_unprivileged_userns` ради успешной проверки. Если окно падает при старте на Ubuntu — не загружен профиль AppArmor (раздел [AppArmor](../../../docs/packaging.md#apparmor)).

## Что сообщить

- Версию и пути собранных файлов.
- Результат каждой выполненной проверки; невыполненные — с причиной.
- Что результат одной ОС не переносится на другие и что пакеты не ставились, если их не ставил владелец.
