# Код Desktop App

Работай в корне репозитория. Правила кода и чем проверяется каждое — [docs/code-style.md](../../../docs/code-style.md); устройство, на которое они опираются, и порядок добавления метода, события, настройки — [docs/development.md](../../../docs/development.md#как-добавить). Если скилл расходится с ними, верны они.

## Перед правкой

1. Найди область в [карте кода](../../../docs/code-map.md) и прочитай её документы-владельцы (`app-code-map`).
2. Прочитай [docs/code-style.md](../../../docs/code-style.md): правила с пометкой «обзором» команда не поймает — их держишь ты.
3. Если изменение — метод сервиса, событие, настройка или страница, иди по рецепту из раздела [Как добавить](../../../docs/development.md#как-добавить) по шагам: он перечисляет все места, которые надо тронуть.
4. Найди образец в шаблоне (список примеров — в [docs/code-style.md](../../../docs/code-style.md)) и пиши так же.

## Во время работы

- Гоняй адресные тесты изменённого: `go test ./internal/<пакет>`; во `frontend/` — `yarn test <файл>`, `yarn typecheck`. Полный прогон — перед коммитом.
- **Тексты — сразу на обоих языках.** Ключ интерфейса — в `frontend/src/i18n/ru.ts` и `frontend/src/i18n/en.ts`; текст Go — в обоих словарях `internal/texts`; код ошибки — в `frontend/src/i18n/error-codes.json` и тексты `errors.<код>` в обоих словарях.
- **Привязки.** Изменил метод сервиса, событие или тип их данных — `wails3 task bindings` и `frontend/bindings` в том же коммите. Руками привязки не правятся.
- Новая зависимость — только с записью решения и причины в `spec/plan/DECISIONS.md`; без решения не добавляй.
- Не отключай проверку, не ставь пропуск теста и `eslint-disable` ради зелёного прогона: исправь причину или спроси владельца.

## Перед коммитом

1. `wails3 task fmt`.
2. `wails3 task check` — запускай в фоне, он длинный.
3. По виду изменения — дополнительные команды из таблицы [Перед коммитом](../../../docs/code-style.md#перед-коммитом): `test:e2e`, `check:race`, `build` и `smoke`, `docs:map`. `check:bindings` сверяет с закоммиченным: до коммита он падает и при верных привязках.
4. Документы-владельцы обновлены в том же коммите (`app-docs`).
5. Перечитай diff по правилам «обзором»: граница Wails, ошибки с контекстом, `context.Context` у долгого, комментарии у экспортируемого, ни одной строки интерфейса в JSX.

Коммит — только по поручению владельца; формат сообщения — раздел «Git» `AGENTS.md`.

## Обзор чужого изменения

Сверь diff с таблицами [docs/code-style.md](../../../docs/code-style.md) построчно: сначала правила «обзором», затем убедись, что команды из «Перед коммитом» действительно запускались. Сообщай расхождения с файлом и строкой, не меняя код без поручения.

## Что сообщить

Что изменено; какие проверки запущены и их итог; какие не запускались и почему; найденные расхождения правил и кода.
