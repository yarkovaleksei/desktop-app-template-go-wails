# Правила интерфейса

Правила для страниц и компонентов фронтенда: компоненты MUI, тексты, тема, окно, проверка. У каждого правила названо, чем оно проверяется: командой или обзором. Как устроены слои фронтенда и как добавить страницу — в [development.md](development.md#страница); правила кода TypeScript — в [code-style.md](code-style.md#typescript-и-react).

## Компоненты

| Правило | Чем проверяется |
| --- | --- |
| Сначала готовые компоненты MUI (`Button`, `Switch`, `ToggleButtonGroup`, `Alert`, `Tabs`, `Stack`); свой компонент — когда в MUI нужного нет | обзором |
| Стили — через тему и проп `sx`; цвета, отступы и шрифты из темы, без значений в коде компонента | обзором |
| Общий компонент для нескольких страниц — в `frontend/src/components/` (образец — `AppUpdates.tsx`) | обзором |
| Элементы управления доступны по роли и имени: у переключателя — подпись, у пояснения — связь с элементом | тесты страниц (`wails3 task test:frontend`) и сквозные сценарии ищут элементы по роли и имени |

## Тексты

| Правило | Чем проверяется |
| --- | --- |
| Ни одной строки интерфейса в JSX: всё через `t("ключ", params)` | `wails3 task lint:frontend` (правило `i18next/no-literal-string`) |
| Новый ключ добавляется сразу в оба словаря: `frontend/src/i18n/ru.ts` (эталон) и `frontend/src/i18n/en.ts` | `wails3 task typecheck` (ключи типизированы по `ru.ts`) и `wails3 task test:frontend` (`frontend/src/i18n/i18n.test.tsx`) |
| Ошибка из Go показывается текстом `errors.<код>` на обоих языках | `wails3 task test:frontend` и `wails3 task test:go` |
| Множественное число — объект с формами `Intl.PluralRules` и параметром `count` (образец — `home.uptime` в словарях) | обзором |
| Смена языка применяется сразу, без перезапуска | `wails3 task test:e2e` (`frontend/e2e/pages.spec.ts`) |

## Тема

| Правило | Чем проверяется |
| --- | --- |
| Цвета — только из токенов `frontend/src/theme/tokens.ts`; тему MUI строит `createAppTheme` | `wails3 task test:frontend` (`frontend/src/theme/theme.test.ts`: палитра взята из токенов) |
| Контраст текста к фону не ниже 4.5:1 в обеих темах | `wails3 task test:frontend` (`frontend/src/theme/theme.test.ts`) |
| Пустое значение темы — как в системе; явный выбор важнее системы | `wails3 task test:frontend` |

## Поведение

| Правило | Чем проверяется |
| --- | --- |
| Не перекладывать работу программы на пользователя: то, что приложение может узнать или сделать само (каталоги, формат пакета, наличие трея), оно делает само; пути от пользователя не спрашиваются | обзором |
| Недоступная возможность не прячется молча: элемент выключен и рядом пояснение, почему (образец — переключатель работы в фоне без трея) | обзором; сам образец — тест `frontend/src/pages/SettingsPage/SettingsPage.test.tsx` |
| Ошибка вызова показывается уведомлением с текстом по коду и не роняет страницу; необработанная ошибка уходит в журнал Go | обзором; граница ошибок — `frontend/src/app/App.test.tsx` |
| Долгая операция показывает состояние и, если можно, отмену (образец — скачивание в `AppUpdates`) | обзором; состояния блока обновлений — `wails3 task test:e2e` |

## Окно и проверка

| Правило | Чем проверяется |
| --- | --- |
| Каждая страница проверена в светлой и тёмной теме, на русском и английском | `wails3 task test:e2e` (`frontend/e2e/pages.spec.ts`), для новой страницы — её сценарий |
| Страница читается и управляется в минимальном окне 960×600: ничего не обрезано, прокрутка — у содержимого, а не у окна | обзором: `wails3 task ui`, окно браузера 960×600, обе темы и оба языка |
| У новой страницы есть сквозной сценарий в `frontend/e2e/`: обе темы, оба языка, основные действия, нет ошибок в консоли и запросов в сеть | обзором (сценарий есть); сами проверки консоли и сети — фикстура `frontend/e2e/fixtures.ts` |
| Состояние для сценария задаётся параметрами адреса моков, а не правкой кода | обзором; параметры — `mockOptionsFromSearch` в `frontend/src/api/mockSource.ts` |

`wails3 task ui` открывает интерфейс в браузере на моках, без Go. В окне приложения на настоящих данных — `wails3 task dev` (настройки разработки живут в `.task/dev-home`).
