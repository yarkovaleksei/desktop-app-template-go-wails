# Интеграция с рабочим столом

Документ описывает возможности, которые связывают приложение с рабочим столом: один экземпляр, состояние окна, трей и работа в фоне, автозапуск и `--hidden`, уведомления, фоновая проверка обновлений. Для каждой — как устроена, какие у неё настройки, где она недоступна и как убрать её из проекта, которому она не нужна.

Код связки — `desktop.go` пакета `main` и пакет `wailsx` из go-desktop-kit; фоновая проверка — `internal/updatecheck`. Порядок запуска, в котором всё это создаётся, — в [development.md](development.md#порядок-запуска). В smoke-режиме (`wails3 task smoke`) трей, автозапуск, уведомления и фоновая проверка не запускаются.

## Где проверено

Сводка проверок шаблона. «Проверено» — возможность запускалась вживую на этой системе; «не проверено» — код есть, но на системе его не запускали.

| Возможность | Linux | Windows | macOS |
| --- | --- | --- | --- |
| Один экземпляр | проверено | не проверено | не проверено |
| Размер, положение, разворот окна | проверено | не проверено | не проверено |
| Трей и работа в фоне | проверено (GNOME с расширением AppIndicator); без хоста значков закрытие окна завершает приложение | не проверено | не проверено |
| Автозапуск и запуск в трей | проверено (XDG autostart) | не проверено | не проверено |
| Уведомления | проверено (GNOME Shell); без службы уведомлений — запись в журнале | не проверено | не проверено |
| Фоновая проверка обновлений | проверены расписание и ответ «выпусков нет»; уведомление о новой версии — тестами | не проверено | не проверено |

Linux проверялся в сеансе X11 (GNOME); Wayland не проверен.

## Один экземпляр

- **Как устроено.** `wailsx.SingleInstance` в `application.Options`. Повторный запуск (ярлык, меню) не открывает второе окно: он завершается, а первое приложение показывает своё окно и выводит его на передний план. Повторный запуск с `--hidden` (автозапуск поверх уже работающего приложения) окно не показывает.
- **Граница экземпляра** — каталог настроек: идентификатор строится из идентификатора продукта и хэша каталога. Поэтому `wails3 task dev` и `wails3 task smoke` (свой `DESKTOP_APP_HOME`) работают рядом с установленным приложением.
- **Настроек нет.**
- **Недоступно:** не встречалось. На Linux проверено: второй запуск завершается сразу с кодом 0, первое окно становится активным. На Windows и macOS не проверено.
- **Как убрать:** удалить поле `SingleInstance` в `main.go`.

## Состояние окна

- **Как устроено.** Окно открывается 1280×800 по центру, минимум 960×600. `wailsx.RestoreWindow` подставляет сохранённые размер, положение и разворот из `window.json` в каталоге настроек; `wailsx.TrackWindow` запоминает их при закрытии окна и выходе. Границы за пределами экранов или меньше минимума не восстанавливаются — окно открывается по умолчанию.
- **Linux.** GTK 4 в Wails v3.0.0 применяет начальный размер ненадёжно, а экраны до запуска неизвестны; обход — внутри `wailsx` (размер и положение ставятся после готовности окна), в `main.go` кода для этого нет. Окно, показанное из трея после запуска с `--hidden`, получает сохранённый размер, но встаёт туда, куда поставит оконный менеджер.
- **Настроек нет.** Сбросить состояние — удалить `window.json`.
- **Недоступно:** не встречалось. На Linux проверено на трёх мониторах; на Windows и macOS не проверено.
- **Как убрать:** удалить вызовы `wailsx.RestoreWindow` и `wailsx.TrackWindow` в `main.go`. `MinWidth` и `MinHeight` окна оставить: без них окно GTK 4 может открыться размером 1×1.

## Трей и работа в фоне

- **Как устроено.** `wailsx.SetupTray` в `desktop.go` создаёт значок с меню «Показать», «Проверить обновления», «Выйти». Тексты меню — из `internal/texts`, на языке настроек; смена языка перестраивает меню без перезапуска. «Проверить обновления» открывает страницу настроек и сразу проверяет. Значок — `build/trayicon.png`, на macOS — шаблонное изображение `build/trayicon-template.png`.
- **Работа в фоне.** Если включена, закрытие окна прячет его, а приложение продолжает работать; вернуть окно — «Показать» в трее или повторный запуск. Выключена — закрытие окна завершает приложение. «Выйти», SIGINT и SIGTERM завершают приложение в любом случае.
- **Настройка:** «Работать в фоне при закрытии окна» (`background`), по умолчанию выключена.
- **Недоступно на Linux без хоста значков StatusNotifierItem** — например, в GNOME без расширения AppIndicator (в KDE хост встроен). Тогда значка нет, переключатель на странице настроек выключен с пояснением, закрытие окна завершает приложение, а в журнал пишется «трей недоступен…». Запись в журнале проверена; поведение без трея покрывает тест kit, вживую сеанс без трея не воспроизводился. В Windows и macOS трей есть всегда; там не проверено.
- **Известное:** подсказка значка в GNOME показывает «Wails», а не название приложения: Wails v3.0.0 на Linux её не применяет.
- **Как убрать:** в `setupDesktop` (`desktop.go`) не вызывать `wailsx.SetupTray`, а `quit` заменить на завершение приложения (`a.Quit`); удалить настройку `background` по рецепту «Настройка» из [development.md](development.md#настройка) в обратном порядке, тексты трея из `internal/texts` и значки трея. Без трея теряют смысл и `--hidden`, и пункт «Проверить обновления»: о новой версии сообщит уведомление.

## Автозапуск и `--hidden`

- **Как устроено.** `wailsx.Autostart` возвращает менеджер автозапуска. На Linux — файл XDG `~/.config/autostart/desktop-app.desktop` с `Exec=<путь к бинарю> --hidden`; путь у AppImage берётся из переменной `APPIMAGE`, а не из точки монтирования. Файл с `Hidden=true` или `X-GNOME-Autostart-enabled=false` считается выключенным — так запись отключают пользователь и настройки GNOME. На Windows и macOS — менеджер автозапуска Wails.
- **Состояние читается из ОС** и в настройках не хранится: пользователь мог выключить запись системными средствами.
- **`--hidden`.** Запуск без окна, сразу в трей, — если включена работа в фоне и есть трей. Иначе окно показывается: без трея до приложения было бы не добраться.
- **Настройка:** «Запускать при входе в систему» на странице настроек.
- **Недоступно:** в smoke-режиме (ошибка `autostart.unavailable`); если ОС отказала — ошибка `autostart.failed` с подробностями. На Linux проверено (запись, `Exec`, описание на языке запуска); на Windows и macOS не проверено.
- **Как убрать:** не создавать менеджер в `setupDesktop`; удалить методы `Autostart` и `SetAutostart` из `SettingsService` (`internal/app/settings.go`), их коды ошибок, переключатель на странице настроек, `wails3 task bindings`. Флаг `--hidden` в `main.go` можно оставить: без автозапуска его никто не передаёт.

## Уведомления

- **Как устроено.** Сервис уведомлений Wails и `wailsx.NewNotifier` в `desktop.go`. Нажатие на уведомление показывает окно и открывает страницу настроек событием `app:navigate`. Сейчас уведомление одно — «вышла новая версия» от фоновой проверки. Отказ системы (нет службы уведомлений, запрет пользователя) не ошибка: он пишется в журнал «уведомление не показано».
- **macOS** показывает уведомления только с разрешения пользователя; приложение спрашивает его один раз, при первом уведомлении, а не при запуске. Не проверено.
- **Настроек нет:** уведомления включает и выключает ОС.
- **Недоступно на Linux без службы `org.freedesktop.Notifications`:** уведомление не показывается, в журнале — запись, приложение работает дальше. Проверено.
- **Как убрать:** не регистрировать сервис уведомлений в `main.go` и не создавать `wailsx.NewNotifier` в `setupDesktop`; фоновую проверку обновлений тогда тоже убрать — сообщить о версии ей будет нечем.

## Фоновая проверка обновлений

- **Как устроено.** `internal/updatecheck`: через минуту после включения и затем раз в сутки цикл вызывает проверку сервиса обновлений. Если вышла новая версия, он один раз на версию показывает уведомление; ответ «актуально» и ошибки уведомлений не дают. Включение и выключение настройки запускают и останавливают цикл без перезапуска; при выходе цикл останавливается.
- **Настройка:** «Проверять обновления автоматически» (`autoCheckUpdates`), по умолчанию выключена: без согласия пользователя приложение в сеть не обращается.
- **Недоступно в сборке из исходников** (нет формата пакета, `--version` печатает `source`): обновиться из приложения нельзя, и цикл не запускается — в журнале «фоновая проверка обновлений не запущена: сборка без формата пакета». Проверено на Linux: сборка с форматом `deb` через минуту обратилась к GitHub и получила «выпусков нет». Уведомление о настоящей новой версии проверено только тестами: у шаблона нет выпусков.
- **Как убрать:** не создавать цикл в `setupDesktop`, удалить пакет `internal/updatecheck` (и его строку в `internal/repodocs/areas.go`), настройку `autoCheckUpdates` и её переключатель. Ручная проверка на странице настроек от этого не зависит.

Обновление пакетов каждого формата описано в документации go-desktop-kit (пакет `updater`).
