# Решения

Действующие решения и открытые вопросы. Правила — раздел «Решения и вопросы» в [AGENTS.md](../AGENTS.md#решения-и-вопросы), образцы записей — [records.md](../templates/records.md#решение).

Следующие номера: **D-010**, **Q-001**.

Решения D-001–D-009 проект наследует от шаблона. Их можно изменить, как любое решение: новым решением, которое заменяет прежнее, вместе с кодом и документами.

## D-001 — Стек: Go, Wails 3, React, MUI

- Источник: шаблон.
- Go 1.26 и Wails `v3.0.0` для приложения, React, MUI и zustand для интерфейса, yarn 4 через corepack. Общий код десктоп-приложения (обновление, каталоги, журнал, процессы, выпуск) — в модуле `github.com/yarkovaleksei/go-desktop-kit`.
- Новая зависимость добавляется только с решением и причиной.
- Причина: одно приложение на Go собирается под Linux, Windows и macOS, интерфейс — веб-технологии в системном WebView без своего браузера в пакете.

## D-002 — Граница Wails: Wails импортируют только `main` и `internal/app`

- Источник: шаблон.
- Ядро (`internal/…`) работает без окна и фронтенда и тестируется обычным `go test`. Сервисы `internal/app` не содержат логики: вызов в ядро, ответ в DTO, ошибка в `*apperr.Error` с кодом. Фронтенд ходит в Go только через `DataSource`. Правило проверяет `internal/archtest`; подробно — [docs/development.md](../../docs/development.md#сервисы).
- Причина: логика не зависит от Wails и проверяется без окна; интерфейс проверяется на моках без Go.

## D-003 — Интерфейс на двух языках: русском и английском

- Источник: шаблон.
- Словари `frontend/src/i18n/ru.ts` и `frontend/src/i18n/en.ts`, тексты Go — `internal/texts`; полноту обоих проверяют тесты. Язык по умолчанию — язык системы, если он не русский и не английский — английский. Строки интерфейса в JSX запрещены линтером. `README.md` переведён в `README.en.md`.
- Не меняет язык документов, комментариев и коммитов: они по-русски.
- Причина: приложение сразу пригодно для пользователей вне русского языка, а словарь без i18n-библиотеки обходится без зависимости.

## D-004 — Версия — только в git-теге

- Источник: шаблон.
- Версия вшивается при сборке через `-X main.version` из `git describe`; файла версии нет. Выпуск — тег `vX.Y.Z`.
- Причина: у версии один источник, который нельзя забыть обновить.

## D-005 — Выпуск собирает CI

- Источник: шаблон.
- По тегу workflow `release` собирает пакеты на Linux, Windows и macOS и складывает их с файлами сумм в черновик выпуска. Локально остаются сверка состава (`wails3 task release:verify`) и публикация черновика (`wails3 task release:promote`). Порядок — [docs/release.md](../../docs/release.md).
- Причина: пакеты трёх ОС не собрать на одной машине, а черновик не виден пользователям до сверки.

## D-006 — Форматы поставки: deb, rpm, пакет Arch, AppImage, установщик NSIS, переносимый exe, dmg

- Источник: шаблон.
- Семь пакетов и три файла сумм в выпуске; список — переменная `RELEASE_FORMATS` в `Taskfile.yml`, подробно — [docs/packaging.md](../../docs/packaging.md#форматы). Пакет знает свой формат по вшитой метке и обновляется из приложения пакетом того же формата.
- Причина: пользователь каждой ОС ставит приложение привычным способом.

## D-007 — Закрытие окна завершает приложение

- Источник: шаблон.
- Работа в фоне с треем включается переключателем в настройках. Проекту, которому нужна фоновая работа по умолчанию, достаточно сменить умолчание настройки ([docs/desktop.md](../../docs/desktop.md#трей-и-работа-в-фоне)).
- Причина: так ведёт себя большинство приложений; скрытое в трее окно удивляет пользователя, который его не включал.

## D-008 — Автоматическая проверка обновлений по умолчанию выключена

- Источник: шаблон.
- Пока пользователь не включил настройку «Проверять обновления автоматически», приложение само в сеть не ходит. Включённая — проверяет при запуске и раз в сутки, о новой версии сообщает уведомление ([docs/desktop.md](../../docs/desktop.md#фоновая-проверка-обновлений)). Ручная проверка в настройках работает всегда.
- Причина: приложение не обращается к сети без согласия пользователя.

## D-009 — Пакеты не подписываются

- Источник: шаблон.
- Без подписи deb, rpm и Windows, на macOS — только ad-hoc. Целостность при обновлении из приложения — сверка SHA-256 с файлом сумм выпуска ([docs/packaging.md](../../docs/packaging.md#подписи-нет)). Подпись и нотаризация — задача бэклога B-002.
- Причина: подпись требует платных сертификатов и учётных записей; без них выпуск собирается в CI без секретов.
