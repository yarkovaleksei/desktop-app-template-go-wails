# Бэклог

Предложения вне плана. Запись не разрешает реализацию: задачу включает в план владелец. Правила — раздел «Бэклог» в [AGENTS.md](../AGENTS.md#бэклог), образец записи — [records.md](../templates/records.md#задача-бэклога).

Следующий номер: **B-008**.

## B-001 — Заменить шаблонную иконку своей

- Статус: предложено.
- Источник: шаблон, предложение для каждого проекта из него.
- Проблема: иконка приложения и значки трея — шаблонные: белое окно на цветной плашке, цвет выведен из слага. Они отличают проект от других проектов из шаблона, но не говорят, что это за приложение.
- Возможная работа: нарисовать иконку 1024×1024 и значки трея и положить их по разделу «Иконка» в [docs/packaging.md](../../docs/packaging.md#иконка).
- Проверка: `wails3 task icons:derive` обновил `.ico` и `.icns`; своя иконка видна в установленном пакете, в трее и в переключателе окон.

## B-002 — Подписать пакеты и нотаризовать сборку macOS

- Статус: предложено.
- Источник: шаблон.
- Проблема: пакеты не подписаны (раздел «Подписи нет» в [docs/packaging.md](../../docs/packaging.md#подписи-нет)): Windows SmartScreen и macOS Gatekeeper предупреждают пользователя при первом запуске.
- Возможная работа: [рецепт подписи и нотаризации](../../docs/recipes/code-signing.md); нужны сертификаты и учётные записи владельца, секреты — в настройках репозитория, не в коде.
- Проверка: установщик Windows и dmg открываются без предупреждений на чистой системе; выпуск собирается в CI с подписью.

## B-003 — Включить Dependabot

- Статус: предложено.
- Источник: шаблон.
- Проблема: версии модулей Go, пакетов npm и GitHub Actions обновляются только вручную; об уязвимой зависимости никто не напомнит.
- Возможная работа: файл `dependabot.yml` в каталоге `.github/` для `gomod`, `npm` (каталог `frontend`) и `github-actions` с редким расписанием и группировкой обновлений; задержка для свежих версий — не меньше `npmMinimalAgeGate` из `frontend/.yarnrc.yml`.
- Проверка: Dependabot открывает PR, `check` на них зелёный.

## B-006 — Перевести на go-desktop-kit приложения, написанные до шаблона

- Статус: предложено.
- Источник: шаблон; при создании шаблона перевод существующих приложений владельца сознательно не делался.
- Проблема: в приложениях владельца, написанных до шаблона, обновление, каталоги, журнал, запуск процессов и инструмент выпуска реализованы каждый раз заново; исправление в go-desktop-kit до них не доходит.

- Проверка: в приложении нет своей копии заменённого пакета, его проверки и выпуск проходят.

## B-007 — Название приложения в трее на Linux

- Статус: предложено.
- Источник: шаблон; найдено при проверке инициализации проекта (2026-11-16).
- Проблема: на Linux заголовок и подсказка значка в трее — «Wails», а не название приложения. В Wails `v3.0.0` на Linux подсказка трея не передаётся, а пустой заголовок StatusNotifierItem подменяется на «Wails» (`pkg/application/systemtray_linux.go`). На Windows и macOS подсказка — `appinfo.Name`.
- Возможная работа: задать трею `Label` с названием приложения только на Linux (на macOS `Label` — текст рядом со значком в строке меню, там он не нужен) — в `wailsx` go-desktop-kit или в `desktop.go`; либо перейти на версию Wails, где подсказка на Linux работает; версия Wails меняется только с решением D-NNN.
- Проверка: `busctl --user get-property <имя> /StatusNotifierItem org.kde.StatusNotifierItem Title` возвращает название приложения; в трее рабочего стола видно название.
