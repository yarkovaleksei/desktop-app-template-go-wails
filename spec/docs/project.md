# Проект

## Продукт

Desktop App — шаблон десктоп-приложения на Go, Wails 3, React и MUI. Из него за один шаг инициализируется новый проект, который сразу собирается под Linux, Windows и macOS, открывает окно и проходит проверки. Разработку по шаблону ведёт агент, поэтому инструкции для агентов, скиллы и папка `spec/` — часть продукта.

Что получает проект из шаблона:

- окно с двумя страницами, «Главная» и «Настройки»: тема, язык интерфейса, работа в фоне, автозапуск, проверка обновлений;
- трей, автозапуск, уведомления ОС, один экземпляр, сохранение размера и положения окна;
- обновление через GitHub Releases пакетом того формата, из которого приложение установлено;
- семь форматов поставки и выпуск через CI по тегу;
- проверки: тесты Go и фронтенда, линтеры, сквозные сценарии на моках, проверка документов и карты кода, smoke-запуск окна на трёх ОС;
- документы, рецепты возможностей, которых нет в базе, правила для агентов и порядок ведения плана.

## Пользователи

Владелец и агент (Claude Code, Codex), которые начинают новое десктоп-приложение и хотят не собирать заново сборку, упаковку, CI и правила работы. Конечные пользователи приложений из шаблона работают на Linux, Windows и macOS.

## Границы

- Шаблон — заготовка, а не библиотека: проект после инициализации живёт сам и обновлений шаблона не получает. Общий код, который проекты получают обновлениями, — в модуле `github.com/yarkovaleksei/go-desktop-kit`.
- Приложение-заготовка хранит только свои настройки и состояние окна в каталоге настроек пользователя. В сеть ходит только для проверки и скачивания обновлений: по кнопке или при включённой автоматической проверке.
- Шаблон собирается и проверяется под именем-заглушкой «Desktop App»: CI шаблона проверяет то же, что получит проект.

## Чего не делаем

- Предметной логики: шаблон не знает, что будет делать приложение.
- Возможностей, нужных не каждому проекту (база данных, второй бинарь, третий язык, Storybook, корзина ОС, подпись пакетов): они описаны рецептами в [docs/recipes/](../../docs/recipes/README.md), чтобы база оставалась минимальной.
- Подписи пакетов и нотаризации: нужны платные сертификаты; это задача бэклога B-002.
- Генератора проекта с вопросами и вариантами: инициализация меняет имена, а остальное проект меняет сам по рецептам.
